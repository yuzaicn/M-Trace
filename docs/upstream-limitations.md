# 上游结论的置信度限制（转录，未经验证部分不得当作已证实）

本文件是 `docs/interface.md` 的附件，作用只有一个：**把分析报告中"已实测"与"未实测"的结论分开记录**，避免它们在实现期被混为一谈。

来源：GUCH-356 分析报告（`analysis-report.md`，Analyzer），第 4、7、9 节。
本项目契约引用该报告的任何数字时，都必须按本文件的口径表述。

---

## 1. 已实测（可离线重跑，可作依据）

全部数字来自一份公开的 468 条真实响应数据集（13 个模型 / 12 个环境）上的 14 组自建实验，纯 Python 可离线复算。**数据集的使用方式与结论推导过程记录在 GUCH-356 的实验目录中**，本仓库不携带该数据集。

| 结论                           | 实测数字                                                                                                   | 用途                                          |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| 参考实现打分核心可独立复现     | 与参考参数逐条比对 **467/468** 一致；库内留一环境 top-1 **0.955**                                          | 证明这条技术路线可迁移，不是玄学              |
| 真正的信号在顺序与重复结构     | 真实采样 χ²/df 中位 **0.332**；lag-1 自相关中位 **−0.587**；distinct/n **0.953**；重复率 **0.047**         | 绝对可信度层（契约第一段）的物理依据          |
| 干扰方向投影与有序块特征零贡献 | 去掉投影 **0.955 → 0.957**；去掉有序块 **0.957**                                                           | 据此在契约里**删除**这两个部件                |
| 库外模型被硬归因是第一问题     | 13 个库外模型 **36/36 全部被硬归因**，平均置信度 **0.748**，与库内正确样本的置信度分布**重叠、阈值分不开** | 两段式决策 + top-N 拒判的直接依据             |
| 防篡改强度弱                   | 加性抖动 σ=2 → 库内准确率 **0.486**；σ=5 → **0.315**；均匀重采样 → **0.073**                               | 「不承诺对抗性场景」这条边界的事实基础        |
| 对文本包装免疫                 | 7 种提示词包装下归因翻转 **0/468**                                                                         | 支持"包装不敏感"的表述                        |
| 库规模曲线                     | 1→0.395 ｜ 2→0.568 ｜ 3→0.615 ｜ 6→0.686 ｜ 12→0.872 ｜ 36→0.955                                           | 冷启动门槛「≥6 个模型」，低于 6 时准确率 <0.7 |
| 样本量需求                     | k=1 → **0.955**；k=2 → **0.987**；k=3 → **1.000**                                                          | 每模型 ≥3 条独立响应的采集要求                |
| 我方架构的家族级结论更稳       | 具体模型 **0.921**，家族 **1.000**                                                                         | MVP 对外主打家族级 + 异常检测                 |
| 无干扰方向下的可信度层拦截率   | 实验 12：对伪随机 / 重采样**近 100% 拦截**                                                                 | 可信度层的设计依据（范围仅限该实验数据集）    |

## 3. 引用规则（给阶段 3/4 的强制口径）

1. **已实测的数字**必须与上表一致，不得四舍五入成更漂亮的数（`0.921` 不写成"约 95%"）。
2. **未实测的能力**（U2–U4、U6）在任何面向用户的产物里都必须写成"设计目标"或直接不写；
   README、报告、CLI 帮助里**不得**出现对 C/D/B 三条路线的效果承诺。
3. **可信度层的"近 100% 拦截率"** 只在实验 12 的数据集范围内成立，
   引用时必须带上范围，不得写成通用保证。
4. 契约与报告引用分析结论时，**"未实测"这一状态本身要传给读者**。
   报告的 `limitations` 与 `degradations` 字段就是它的落点。

## 4. 这些限制如何影响契约（逐条落点）

| 限制                     | 契约落点                                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| U1 未做端到端探测        | `src/types/probe.ts` 的 `TransportPort` 必须能被真实 HTTP mock 完整替换；L4 门禁覆盖 E01–E14                                     |
| U2/U3 行为与协议层未实测 | `ChallengeFamilyDescriptor.priority` 标 `'P1'`、`status` 可标 `'reserved'`；`TransportFeatures` 只要求**被采集**，不要求参与判定 |
| U4 文本统计指纹未实测    | `familyRegistry` 中留扩展位，标注 `'P2'`，契约不定义其特征                                                                       |
| U5 跨时间稳定性未测      | `ReferenceEntry.collectedOn` 必填；`degradations` 保留 `'fingerprint-drift-unverified'` 这类键的位置                             |
| U6 竞品未扫描            | 报告与 README 的 `limitations` 不含竞品比较结论；对比只作为产品文档的定性描述                                                    |
